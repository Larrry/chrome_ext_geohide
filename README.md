# Domain Locale & Timezone (Chrome MV3)

**Версия 1.1.0.** Основана на проверенной v1.0; механизм ранней регистрации скрипта (`MAIN` / `document_start`) сохранён.

Локальное расширение, изменяющее стандартные сигналы языковых предпочтений и таймзоны **только на выбранных доменах**. Без серверов, аналитики и сторонних библиотек.

## Обновление с v1.0 (важно для сохранения ID)

1. Распакуйте `chrome-locale-timezone-switcher-v1.1.0.zip` **в отдельное временное место**.
2. Замените файлы **в той же папке**, из которой Chrome уже загрузил v1.0. Не загружайте вторую копию из другого пути: у неё может появиться другой ID и чистые настройки.
3. Откройте `chrome://extensions` и нажмите **Обновить / Reload** на карточке расширения. Сохранённые домены и локали останутся в `chrome.storage.local` прежнего расширения.
4. Перейдите в «Настроить домены» и нажмите **Сохранить и применить**: это также очистит устаревшие разрешения к сайтам. Обновите нужные вкладки.

## Новое в v1.1.0

- **Общий выключатель** в popup по нажатию на значок: отключает/включает все домены без изменения отдельных галочек.
- **Красный бейдж `OFF`** на значке Chrome при общем выключении; при включении исчезает.
- **История значений**: поля локали и таймзоны показывают все ранее сохранённые значения. История не удаляется вместе с правилом. Начальная история подхватывается из правил v1.0.
- **Очистка разрешений**: при сохранении правил расширение сверяет доступы, выданные именно ему (`chrome.permissions.getAll()`), со списком настроенных доменов и отзывает ненужные (`chrome.permissions.remove()`). Разрешения для сохранённых, но временно отключённых доменов остаются. Дополнительно сверка выполняется при запуске/обновлении расширения. Если Chrome отказывает в отзыве, это отображается в настройках.

**После переключения общего OFF или ON обновите открытые вкладки:** уже запущенные JavaScript-скрипты страницы не выгружаются задним числом; новое состояние гарантируется для следующих загрузок. Отключение убирает зарегистрированный скрипт и динамические HTTP-правила.

## Установка

1. Распакуйте ZIP в постоянную папку (сам ZIP Chrome не загружает как unpacked-расширение).
2. В Chrome откройте `chrome://extensions`, включите **Режим разработчика** и нажмите **Загрузить распакованное расширение** (Load unpacked). Выберите папку `chrome-locale-timezone-switcher` с файлом `manifest.json`.
3. На карточке расширения откройте **Сведения / Details** и включите **Allow User Scripts / Разрешить пользовательские скрипты**. В Chrome 138+ это отдельный переключатель; одного «Режима разработчика» недостаточно.
4. Нажмите значок расширения → **Настроить домены**. Добавьте домен (например, `example.com`), локаль (`en-US`) и идентификатор IANA (`America/New_York`). Нажмите **Сохранить и применить** и разрешите доступ к выбранным сайтам.
5. Обновите открытую страницу. Подмена выполняется в MAIN world на стадии `document_start`.

Правило для `example.com` действует на сам домен и все поддомены. При перекрытии более узкий домен имеет приоритет. Для временного отключения используйте галочку отдельного правила либо общий переключатель в popup. Для удаления правила нажмите «Удалить» и сохраните; ранее выданный доступ к удалённому сайту будет отозван.

## Проверка

На **подходящем** сайте откройте DevTools → Console:

```js
({
  language: navigator.language,
  languages: navigator.languages,
  locale: Intl.DateTimeFormat().resolvedOptions().locale,
  numberLocale: Intl.NumberFormat().resolvedOptions().locale,
  timeZone: Intl.DateTimeFormat().resolvedOptions().timeZone,
  utcOffsetMinutes: new Date().getTimezoneOffset(),
  localDate: new Date().toString(),
  dateFromLocalParts: new Date(2026, 0, 1, 12, 0).toISOString(),
  localeNumber: (1234567.89).toLocaleString()
})
```

HTTP-заголовок `Accept-Language` проверьте в DevTools → Network → первый запрос документа → Request Headers. Для некоторых запросов Chrome показывает заголовки до вмешательства расширений; внешний эхо-сервис, находящийся на разрешённом домене, даст более надёжную проверку.

## Что именно делается

- `navigator.language`, `navigator.languages`; старые `userLanguage` / `browserLanguage` / `systemLanguage`, только если они существуют.
- Стандартные конструкторы `Intl`: DateTimeFormat, NumberFormat, Collator, PluralRules, RelativeTimeFormat, ListFormat, DisplayNames, Segmenter, DurationFormat. Если сайт явно передал локаль, она сохраняется. `Intl.DateTimeFormat` подставляет таймзону по умолчанию, если сайт её не указал.
- `Date`: локальные геттеры и сеттеры, `getTimezoneOffset`, `toString`, `toDateString`, `toTimeString`, `toLocale*`, конструктор с числовыми компонентами, распространённый ISO datetime без зоны и `Date.parse` для такого ISO. Учитываются исторические изменения смещения и летнее время (IANA/DST), неоднозначные часы при переходе на DST.
- `Number` / `BigInt` — `toLocaleString`; `String` — `localeCompare`, `toLocaleLowerCase`, `toLocaleUpperCase`.
- `Temporal.Now.timeZoneId()` при наличии API.
- HTTP `Accept-Language` на навигациях к выбранным доменам и на запросах, инициированных выбранными доменами, если у расширения есть необходимые разрешения для назначения запроса.

## Ограничения (важно)

1. Нельзя гарантировать **абсолютно все** косвенные признаки системного региона: установленные шрифты, голоса speechSynthesis, раскладка клавиатуры, IP-геолокация, WebRTC, серверные данные и любые fingerprinting-техники не подменяются.
2. Код не внедряется в Web Workers, Service Workers, `about:blank`/`blob:`-фреймы и изолированные кросс-доменные iframe (если их домены не в списке). На страницах, уже открытых при смене профиля, требуется обновление.
3. Для кросс-доменных `fetch`/XHR заголовок `Accept-Language` может остаться прежним из-за модели разрешений Chrome: расширение запрашивает доступ лишь к доменам из вашего списка. Для запросов, выполняемых **внутри** Web Worker, JS-подмена тоже не действует.
4. Парсинг нестандартных строк в `new Date('…')`/`Date.parse()` может использовать системную таймзону. Реализован стандартный вид `YYYY-MM-DDTHH:mm[:ss[.sss]]` без зоны. Варианты с `Z` / явным смещением остаются абсолютным временем.
5. Уже захваченные сайтом ссылки на оригинальные функции, особенности движка/переходов времени и защита от подмены могут обнаружить фактическое окружение. Это инструмент совместимости/тестирования, **не антидетект-браузер**.
6. Chrome не разрешает расширениям внедрять код в `chrome://` и некоторые привилегированные страницы.

## Приватность и права

Права на сайты запрашиваются отдельно для доменов, которые вы добавили и включили. Настройки хранятся в `chrome.storage.local`. Сеть не используется для хранения/отправки данных. API `declarativeNetRequest` меняет только заголовок `Accept-Language` по правилам. После удаления/переименования правила и сохранения расширение пытается отозвать ненужные **собственные** разрешения на сайты через `chrome.permissions.remove()`. Выданные разрешения для ещё сохранённых правил не отзываются, даже если соответствующее правило выключено. Разрешения, вручную добавленные этому расширению в Chrome, но отсутствующие среди его правил, также могут быть удалены. Успех отзыва зависит от Chrome; при неудаче статус сообщит об этом.

## Файлы

- `manifest.json` — конфигурация MV3
- `options.html`/`options.js`/`style.css` — редактор доменов
- `popup.html`/`popup.js` — быстрое состояние
- `background.js` — регистрация пользовательского скрипта и DNR правил
- `inject.js` — подмена в контексте страницы
- `tests/` — smoke tests
